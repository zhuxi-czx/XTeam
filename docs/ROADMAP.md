# XTeam 规划路线

## 愿景

XTeam 想做的不是「人发指令、AI 执行」的工具，而是**人和 Agent 组成一支团队**：

- **Agent 负责执行**：拆解、调研、撰写、分析、设计，按各自的能力分工
- **人负责判断**：定目标、在关键节点拍板、验收结果
- **团队会成长**：执行过程中的经验沉淀为记忆，下次做得更好
- **一切围绕目标**：每个任务都能追溯到它服务的目标，进度一目了然

领域模型（`packages/core/src/types.ts`）从第一天起就按这个愿景设计，包含了人、Agent、对话、任务、目标、决策、记忆。

## 下一步（按优先级）

### P0 · 决策节点：让「人机协同」真正成立

现在 Agent 会从头跑到尾，人插不上手。目标是：

- 编排在关键节点暂停（比如规划完成后、方案有多个选项时），生成一条 `decision` 消息，推给人
- 人在对话里选择或修改方案后，编排从断点继续
- 工作台展示「待你决策」的数量和入口
- 任务状态新增「等待决策」

### P1 · 记忆

- 任务完成后，自动提炼值得长期保留的结论，写入 `memories`
- 规划和执行时，把相关记忆作为上下文
- 提供记忆的查看、编辑和删除入口

### P1 · Agent 管理补全

- 在界面上创建和编辑 Agent：能力标签、模型、系统提示词
- 用 Agent 自身的 `system_prompt` 执行任务（目前所有 Agent 共用一段通用提示词）

### P2 · 任务协作

- 支持子任务（`parent_task_id`）
- 任务之间可以传递上下文：后一个任务能拿到前一个任务的产出
- 互不依赖的任务并行执行
- 失败任务可以单独重试

### P2 · 多人团队

- 用户体系与登录
- 对话邀请多人参与
- 区分权限（owner / admin / member）

### P3 · 部署与基础设施

- 数据层迁移到 Supabase（`packages/db` 已预留）
- 抽出共享 UI 组件（`packages/ui` 已预留）
- 自动化测试和 CI

## 已知问题

| 问题 | 位置 | 影响 |
|---|---|---|
| `PATCH /api/tasks/:id` 会把请求体里的任意字段名拼进 SQL | `apps/server/src/routes/tasks.ts` | **SQL 注入风险**，需要改成字段白名单 |
| 前端 API 地址的默认值是一个局域网 IP | `apps/web/src/lib/api.ts` | 没设 `NEXT_PUBLIC_API_URL` 时连不上后端 |
| 编排消息的发送者名字写死在代码里 | `apps/server/src/routes/orchestrate.ts` | 需要等用户体系上线后改掉 |
| 对话历史把所有非人类消息都当作 `assistant` | `apps/server/src/routes/chat.ts` | 多个 Agent 参与时，模型分不清是谁说的 |
| 没有身份验证，CORS 全开 | `apps/server/src/index.ts` | 只适合本地使用 |
| 没有自动化测试 | — | 目前靠手动加浏览器端到端验证 |
